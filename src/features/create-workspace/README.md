# Create a workspace

> A workspace is the first thing anyone needs in Atlas and the last thing they
> want to think about. Today it is one long form, and it is where most new
> accounts stall.

**Designer** Rowan Ellis · **Product** Devon Park · **Release** Atlas 4.2

## The problem

Creating a workspace asks for everything up front — name, type, visibility,
members, retention, default view — on a single screen. Most of it cannot be
answered on day one, so people either guess or leave. The ones who guess come
back within the week to rename or reconfigure what they made.

## What changes

Four short steps instead of one long form. Each step asks for one kind of
decision, and only the name is genuinely required. Everything else has a sane
default and can be changed after the workspace exists.

## Principles

- **Essentials first.** Nothing is required that could be edited later.
- **Never lose work.** A problem is reported where it happened, not at the end.
- **Reversible by default.** Every choice on these screens can be changed afterwards.
- **Always an exit.** Configure can be skipped; Review can be reversed.

## Who it's for

- **New account owners** setting up their very first workspace.
- **Team leads** creating a shared space for a project that already exists.

## Success signals

- More people who start the flow finish it.
- Fewer workspaces renamed in their first week.
- Fewer questions about who can see a workspace.

## Out of scope

Templates, billing and organization-wide policy. Those are tracked separately
and are deliberately not part of this flow.
